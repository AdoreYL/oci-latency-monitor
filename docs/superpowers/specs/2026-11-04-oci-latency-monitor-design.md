## 1. 目标与背景 (Purpose & Goals)

为用户提供一套开箱即用、可通过 `docker compose up -d` 部署在任意 Linux 服务器并配合反向代理（HTTPS 域名）访问的**甲骨文云全球 40 节点实时网络监控工具**。

### 核心成功标准 (Success Criteria)
1. **双视角持续测速**：
   - **🏠 本地浏览器模式（默认）**：测量访问者当前本地网络到甲骨文全球 40 个区域终端节点的实时 HTTPS Keep-Alive RTT 延迟、丢包/超时率与波动趋势。
   - **🖥️ 服务器后端模式**：由部署容器后端并发执行 TCP/ICMP 探测，测量服务器所在机房到甲骨文全球 40 个区域的真实网络延迟与丢包率（Packet Loss %）。
2. **高度还原并增强 UI**：
   - 保持参考截图的经典视觉风格（深蓝渐变背景、顶部实时进度面板、4 大概览指标卡片、亚太/欧洲/美洲/中东非洲 2×2 分区卡片）。
   - 每个节点展示：**状态指示灯、地区名称、目标域名、丢包率标签、当前延迟、行内迷你历史折线图 (Sparkline)、平均/最低/最高延迟徽章**。
   - 点击任意节点可展开/弹窗查看该节点的**详细历史延迟波动大图（最近 50 轮采样曲线）**。
3. **反向代理零配置兼容**：
   - 前后端同源托管于同一端口（默认 `6689:3000`），所有 API 请求均使用相对路径（`/api/...`），在任何二级域名或 HTTPS 反代下无跨域（CORS）或混合内容（Mixed Content）报错。

## 3. 组件与接口设计 (Components & Data Flow)

### 3.1 节点数据源与官方新区域自动同步 (`src/regions.js`)
1. **内置 40 节点离线保底**：包含甲骨文云全球 40 个官方商业区域（亚太 10、欧洲 11、美洲 13、中东与非洲 6），每个节点结构如下：
   - `id`: 区域标识符（如 `ap-tokyo-1`、`ap-seoul-1`）
   - `name`: 中文名称与英文城市名（如 `日本东京 (Tokyo)`）
   - `group`: 所属大洲分组（`apac` | `europe` | `americas` | `mea`）
   - `host`: 测速目标域名（`objectstorage.<id>.oraclecloud.com`）
2. **官方 SDK 源自动同步机制 (`syncOfficialRegions`)**：
   - 从甲骨文官方开源 SDK 仓库（`oracle/oci-python-sdk` 的 `regions_definitions.py`）拉取最新商业云（`OC1` / `oraclecloud.com`）区域代码。
   - 若发现不在内置列表中的新区域代码，先通过 `dns.promises.lookup` 校验 `objectstorage.<new_id>.oraclecloud.com` 是否已正式上线解析出 IP；校验通过后按前缀自动归入四大洲并加入运行时白名单。
   - 支持服务启动/每 24 小时后台静默同步，也支持前端点击“同步官方最新节点”按钮（调用 `POST /api/regions/sync`）手动触发。

### 3.2 后端服务 (`src/server.js`)
基于轻量级 Node.js HTTP/Express 服务，监听容器内 `3000` 端口：
1. `GET /api/health`
   - 返回服务健康状态与运行时间，供 Docker Healthcheck 及反代存活探针使用。
2. `GET /api/regions`
   - 返回四大洲分组及 40 个节点配置清单。
3. `GET /api/ping`（支持单节点 `?id=ap-tokyo-1` 或批量并发探测）
   - **探测机制（ICMP + TCP 443 双保险）**：
     - 优先使用高精度的 TCP 443 握手测速（`net.Socket` 连接 `objectstorage.<id>.oraclecloud.com:443`，计算 `connect` 耗时并立即销毁连接），因为部分云服务器/Docker 容器默认禁用原始 ICMP Socket 权限或云厂商限流 ICMP，而 TCP 443 100% 穿透且精确反映真实 HTTPS 建连 RTT；同时支持可选的系统 `ping` 命令探测。
   - **并发控制**：后端内置并发池（每批并发 10 个节点，单节点超时时间 `3000ms`），单轮 40 节点全量探测在 1.5~2.5 秒内完成。
   - **返回格式**：
     ```json
     {
       "timestamp": 1793802000000,
       "results": {
         "ap-tokyo-1": { "ok": true, "latency": 48, "method": "tcp" },
         "us-ashburn-1": { "ok": true, "latency": 182, "method": "tcp" }
       }
     }
     ```

### 3.3 前端应用 (`public/index.html`, `public/app.js`, `public/style.css`)
1. **状态管理 (`nodeState`)**：
   - 每个节点维护最近 `50` 次探测记录数组 `history`（记录延迟数值或 `null` 表示超时）、总发送次数 `sent`、超时失败次数 `lost`。
   - **丢包率计算**：`lossRate = Math.round((lost / sent) * 100)`（显示为 `丢包 0%`，当 `>0%` 时高亮橙色/红色预警）。
   - **统计指标**：实时计算 `current`（当前延迟）、`avg`（有效样本均值）、`min`（历史最低）、`max`（历史最高）。
2. **双模式切换**：
   - 切换测速模式（`本地电脑测速` ⇄ `服务器容器测速`）时，自动重置当前统计基线并立即启动新模式的第一轮检测，顶部状态栏清晰提示当前测速来源。
3. **折线图可视化**：
   - **行内迷你折线图 (Inline Sparkline)**：每个节点右侧/中部内嵌 `110×28px` 的 SVG 动态折线图，随每轮测速平滑更新，颜色随当前延迟等级动态变化（绿 `<150ms`、橙 `150~300ms`、红 `>300ms`）。
   - **点击展开详情弹窗 (Detail Modal)**：点击任意节点行弹出高清 Canvas/SVG 历史波动折线图，展示最近 50 次采样的具体数值刻度、平均线、丢包标记点。

## 4. 异常处理与边界防护 (Error Handling & Security)

1. **单节点超时隔离**：无论是前端 `AbortController`（超时 `4000ms`）还是后端 `net.Socket`（超时 `3000ms`），单个节点超时绝不阻塞整轮进度，自动记为一次丢包（`timeout: true`）并更新丢包率。
2. **防并发堆积**：上一轮全量测速完全结束后，再按设定的刷新间隔（2秒 / 3.5秒 / 5秒 / 10秒）调度下一轮定时器，防止弱网环境下请求堆积卡死浏览器。
3. **安全性**：后端 `/api/ping` 严格校验 `id` 是否在白名单 `OCI_REGIONS` 内，杜绝任意地址探测（SSRF 漏洞防护）。
